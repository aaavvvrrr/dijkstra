Данный проект представляет собой **интеллектуальный сервис морской маршрутизации (Maritime Routing Engine)**, построенный на основе исторических данных АИС (Автоматической идентификационной системы), физических ограничений судов и геопространственных правил. 

Сервис состоит из движка маршрутизации (написанного на Python/NumPy), асинхронного API (FastAPI + WebSockets) и интерактивного фронтенда (HTML/Leaflet).

Ниже приведено максимально подробное описание того, как это работает, что можно настраивать и какие файлы необходимы.

---

### 1. Как работает алгоритм (Логика ядра)

Сервис не использует стандартные векторные графы (как OpenStreetMap). Вместо этого он ищет путь прямо по **растровой сетке (пикселям)**, которая покрывает весь Земной шар.

1. **Компенсация сферичности Земли:** Алгоритм учитывает, что Земля круглая. Физическая ширина пикселя на экваторе больше, чем на полюсах. Для этого используются формулы гаверсинуса (Haversine) и предварительно рассчитанные массивы косинусов широт (`self.cos_lats`), чтобы точнее считать диагональные и прямые перемещения в километрах.
2. **Алгоритм поиска пути (Weighted A* с иерархией):**
   * **Грубая сетка (Coarse Grid):** При старте сервера растр сжимается в 20 раз. На этой грубой сетке запускается алгоритм заливки, который находит связные водоемы (определяет, где Мировой океан, а где изолированные озера, например, Каспийское море). Это не дает алгоритму пытаться строить маршрут из Черного моря в озеро Виктория (выдаст ошибку сразу). 
   * **Эвристика:** Для каждой новой задачи сначала быстро рассчитывается приблизительное время до цели по грубой сетке. 
   * **Точный поиск:** Затем запускается классический A* по пикселям оригинального размера, который использует грубую эвристику для сверхбыстрого направления поиска. Поиск транслируется клиенту в реальном времени через WebSocket («щупальце» на карте).
3. **Оценка времени (Monte Carlo Simulation):** Из-за погоды и течений судно не всегда идет со средней скоростью. Сервис использует среднюю скорость и её стандартное отклонение (SD) в каждом пикселе. В конце строится Гамма-распределение и проводится 10 000 симуляций маршрута. Это дает три значения ETA (времени прибытия): ожидаемое (среднее), оптимистичное (5-й перцентиль) и пессимистичное (95-й перцентиль).

### 2. Входные параметры (Что задает пользователь/клиент)

Через фронтенд (или напрямую по WebSocket API) можно передать следующий набор параметров:

* **Координаты:** Точки старта (`start_lon`, `start_lat`) и финиша (`end_lon`, `end_lat`). Если они падают на сушу, алгоритм с помощью BFS (поиска в ширину) ищет ближайшую «глубокую воду» в заданном радиусе.
* **Тип судна (`vessel_type`):** `all`, `tanker`, `cargo`, `fishing`, `passenger`. От этого зависит, какие растры скорости/дисперсии будут загружены в память.
* **Габариты судна:**
  * **Осадка (`draft` в метрах):** Важнейший параметр. К нему прибавляется запас под килем (UKC = 2 метра). Алгоритм на лету проверяет батиметрию (глубину) в каждом пикселе. Если глубина меньше `draft + 2.0`, пиксель считается непроходимым.
  * **Длина (`vessel_length`) и Ширина (`vessel_width`):** Используются для прохождения узких мест (каналов, шлюзов).
* **Экологические зоны (SECA - Sulphur Emission Control Areas):**
  * `calc_seca` (boolean): Просто подсчитать, сколько километров маршрута прошло по зонам строгих выбросов (влияет на расчет расхода дорогого топлива).
  * `avoid_seca` (boolean): Алгоритм будет пытаться обогнуть зоны SECA. Штраф (стоимость прохода) за пиксель в SECA увеличивается в 5 раз (`penalty = 5.0`).
* **Запрещенные узкие места (`forbidden_chokepoints`):** Массив ID шлюзов/каналов, которые принудительно запрещено пересекать.

### 3. Необходимые файлы и структура данных

Для работы `SphericalRasterRouter` требуется заранее подготовленная папка `data/processed/`. Файлы генерируются с помощью скрипта `preprocessing/pipeline.py`.

#### Обязательные базовые файлы (Base rasters):
1. **`eff_vel_all.tif`** — Базовый растр эффективной скорости (в узлах или км/ч) для всех типов судов. Если специфичных растров нет, движок откатится на него. Он же используется для инициализации матрицы мира.
2. **`eff_sd_all.tif`** — Растр дисперсии (Standard Deviation) для всех судов. Нужен для Монте-Карло симуляций.

#### Специфичные растры судов (Опционально, но нужны для выбора типа судна):
Движок динамически подгружает и кэширует в RAM эти файлы, если пользователь выбирает соответствующий тип:
* **`eff_vel_tanker.tif`** / **`eff_sd_tanker.tif`**
* **`eff_vel_cargo.tif`** / **`eff_sd_cargo.tif`**
* **`eff_vel_fishing.tif`** / **`eff_sd_fishing.tif`**
* **`eff_vel_passenger.tif`** / **`eff_sd_passenger.tif`**

#### Географические и физические ограничители:
1. **`depth_meters.tif`** — Батиметрия (например, GEBCO). Значения — отрицательные высоты (глубины). Если файл есть, включается проверка на мель (с учетом осадки судна `draft`). Значения NoData (суша) обычно равны 0 или большим положительным числам.
2. **`seca_mask.tif`** — Бинарная маска зон контроля выбросов серы/азота (ECA/SECA). 1 — зона SECA, 0 — остальной океан. Генерируется из `seca_zones.geo.json`.
3. **`chokepoints.tif`** — Растр узких мест (Суэцкий канал, Панамский канал, Босфор и т.д.). Каждый пиксель канала содержит числовой ID (1, 2, 3...). 0 — обычная вода.

#### Конфигурационные файлы:
1. **`chokepoints_config.json`** — Связывает ID из растра `chokepoints.tif` с физическими характеристиками канала. 
   * *Пример:* Если Панамский канал имеет ID `1`, то в JSON будет прописано: `{"1": {"name": "Panama Canal", "max_length": 366.0, "max_width": 51.25, "max_draft": 15.2}}`.
   * *Логика:* Если пользователь введет ширину судна 55 метров, движок найдет ID `1`, добавит его в список `forbidden_cp`, и алгоритм A* физически не сможет пройти через пиксели со значением `1`, вынуждая судно идти вокруг мыса Горн.
2. **`app/static/oceans-seas.geo.json`** — GeoJSON контуры берегов для красивой отрисовки границ на фронтенде (в Leaflet), а также используется в пайплайне для "прожигания" качественной маски суши поверх треков АИС.

### Резюме пайплайна
Если к вам поступают новые исторические данные АИС:
1. Вы прогоняете их через `RasterPreprocessor` (`pipeline.py`). Он сгладит треки (Gaussian filter), выровняет аномалии через сигмоиду (штрафуя зоны с малым количеством треков) и обрежет сушу.
2. Сгенерированные TIFF-файлы кладутся в папку.
3. FastAPI при старте читает эти растры, строит графы связности морей (выплевывая `debug_connectivity.tif`) и готов мгновенно обслуживать запросы по WebSockets с отрисовкой слоев через собственный встроенный Tile Server (`/tiles/...`).
